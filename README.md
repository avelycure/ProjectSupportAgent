# Project Support Agent

Локальный сервис поддержки с двумя интерфейсами: [лендинг и чат пользователя](http://127.0.0.1:4173/) и [админка менеджера](http://127.0.0.1:4173/admin). Агент отвечает по Markdown-документации проекта с локальным RAG-поиском и облачной OpenAI-совместимой моделью. Когда пользователь просит позвать оператора, сервис создаёт тикет через MCP. Менеджер видит историю беседы, отвечает в тот же чат и закрывает обращение.

Код не привязан к Invest Manager: каждый продукт описывается отдельной папкой `projects/<id>/`. В репозитории уже есть документация Invest Manager; реальных пользователей и тикетов в Git нет. Личное Obsidian-хранилище сервис не читает.

## Быстрый запуск

Нужен Node.js 22 или новее.

```bash
npm install
cp secrets/keys.example secrets/.env
# Укажите CLOUD_API_KEY, CLOUD_BASE_URL, CLOUD_MODEL и ADMIN_PASSWORD в secrets/.env
npm start
```

Откройте <http://127.0.0.1:4173/>. Админка: <http://127.0.0.1:4173/admin>, пароль — значение `ADMIN_PASSWORD` из локального `secrets/.env`. По умолчанию сервер слушает только `127.0.0.1`; внешнего деплоя нет. `secrets/.env` и история обращений в `var/` исключены из Git.

Без облачного ключа агент показывает найденные выдержки из документов. С ключом он формирует связный ответ. Локальная LLM не используется. Для совместимых моделей с разными параметрами лимита токенов поддержаны `max_tokens` и `max_completion_tokens`.

## Как это работает

1. Посетитель выбирает продукт и спрашивает о нём в чате. Список тикетов ему не показывается.
2. Агент находит подходящие разделы Markdown-документации и отвечает с источниками. История разговора хранится локально для продолжения беседы.
3. Команда в чате «позови оператора» или близкая просьба о специалисте создаёт тикет. До этого момента тикет не создаётся.
4. Менеджер входит в админку, видит очередь тикетов, читает всю историю и отправляет ответ. Посетитель получает его в том же чате без перезагрузки страницы.
5. После закрытия тикета посетитель снова общается с агентом.

CRM реализована через настоящий локальный stdio MCP-сервер. Веб-сервер вызывает его инструменты для чтения и записи обращений. Данные хранятся в JSON в папке `var/`. Подробнее: [архитектура](docs/architecture.md), [MCP](docs/mcp.md), [безопасность](docs/security.md).

## Подключить другой продукт

Создайте `projects/<id>/project.json` и Markdown-файлы в `projects/<id>/docs/`. Формат описан в [docs/project-format.md](docs/project-format.md). Документы перечитываются при запросах; JSON с пользователями и тикетами вручную создавать не требуется.
