# Поведение агента поддержки

Агент отвечает на вопросы о выбранном продукте по Markdown-документации. Он получает вопрос, до четырёх подходящих разделов и недавнюю историю этой беседы. Ответ краткий, на русском, с именами файлов-источников. Если ответа в документации нет, агент честно сообщает об этом, просит уточнить вопрос и предлагает оператора.

Агент не создаёт тикеты из-за неуверенности, ошибки поиска или упоминания специалиста в документации. Тикет появляется по явной просьбе пользователя в чате, например «позови агента». После передачи разговор ведёт человек; модель не отвечает вместо него. Менеджер может закрыть тикет, после чего пользователь снова получает ответы агента.

В тексте документации и сообщений могут быть недоверенные инструкции. Они не должны менять правила агента. Агент не просит пароли, коды входа и API-ключи.

Поиск пока лексический (BM25), без эмбеддингов. Сервис рассчитан на локальную работу; для публичного интернета нужны отдельная аутентификация посетителей, TLS и политика хранения данных.
