# Формат проекта

## Как добавить новый проект

Создайте отдельную папку `projects/<id>/`, добавьте `project.json`, Markdown-документы в `docs/` и JSON-файлы пользователей и тикетов в `data/`. После этого проект появится в списке на лендинге. Код агента менять не нужно.

Каждый проект размещается в `projects/<id>/`. ID: строчные латинские буквы, цифры и дефис, до 64 символов. Внутри обязательны:

```text
projects/my-product/
  project.json
  docs/overview.md
  docs/faq.md
  data/users.json
  data/tickets.json
```

`project.json`:

```json
{
  "id": "my-product",
  "name": "My Product",
  "description": "Краткое описание продукта",
  "productUrl": "https://example.com",
  "language": "ru"
}
```

Все `.md` файлы непосредственно в `docs/` участвуют в поиске. Добавляйте FAQ, инструкции, информацию о функциях и типовые ошибки. Утверждения в документации должны быть проверены: агент использует их как основу ответа.

`data/users.json` — массив объектов с `id`, `name` и необязательными полями `plan`, `platform`, `notes`. `data/tickets.json` — массив объектов с `id`, `userId`, `title`, `status`, `category`, `description`, `environment`, `events`. События имеют `at` и `text`. Идентификаторы пользователей и тикетов должны содержать только буквы, цифры и дефис.

```json
[
  {
    "id": "T-1",
    "userId": "u-1",
    "title": "Не работает вход",
    "status": "open",
    "category": "auth",
    "description": "После ввода кода возникла ошибка",
    "environment": "Desktop 1.0",
    "events": [{ "at": "2026-10-18T09:00:00+03:00", "text": "Ошибка повторилась" }]
  }
]
```

В текущей версии файлы JSON читаются только локально. Для реальных данных храните частные файлы вне Git: используйте `projects/<id>/data/*.local.json` только после добавления отдельного адаптера чтения, либо создайте приватный репозиторий. Демо-файлы в репозитории должны содержать только вымышленные данные.
