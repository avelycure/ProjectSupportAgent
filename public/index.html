Один агент для разных проектов. Он находит ответ в документации, запрашивает контекст тикета через MCP и объясняет решение с указанием источников.

Открыть демо-чат ↗Как это устроено ↓

Работает на 127.0.0.1. Данные CRM остаются в JSON на вашем компьютере. Для связного ответа нужен ключ облачной модели.

01 / ПРИНЦИП РАБОТЫ

От вопроса до ответа —
без догадок.

Агент связывает вопрос с тем, что уже известно о продукте и конкретном обращении.

01
▤

Ищет в документации

Разбивает Markdown по разделам и отбирает подходящие фрагменты локальным поиском BM25. Проект можно сменить одним выбором.

02
⌘

Сверяется с CRM

Через локальный MCP-сервер получает выбранный тикет, его историю и сведения о пользователе из JSON.

03
✳

Даёт проверяемый ответ

Облачная модель получает только найденные фрагменты и контекст выбранного тикета. Ответ показывает файлы-источники и отделяет факты от предположений.

02 / АРХИТЕКТУРА

Один движок.
Разные продукты.

Каждый проект — отдельная папка с описанием, документацией, пользователями и тикетами. Для нового продукта достаточно добавить его файлы: код агента остаётся общим.

✓

Демо-проект: Invest Manager
Примеры обращений про Telegram, RSS и связанные заметки. Все пользователи и тикеты в демо вымышлены.

● ● ●projects/<project-id>/
project.json          # имя и описание
docs/
  faq.md              # ответы на вопросы
  overview.md         # описание продукта
  troubleshooting.md  # диагностика
data/
  users.json          # контекст пользователя
  tickets.json        # история обращений
MCP tools: list_projects · list_tickets · get_ticket · get_user
